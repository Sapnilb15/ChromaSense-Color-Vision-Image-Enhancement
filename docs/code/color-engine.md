# Color Engine

`src/color_engine/` is a separate Python package, `color_engine`, with no web framework dependency. It holds the image pipeline (five numbered filters) and the color rules they share. It makes no network calls and reads no environment variables.

## Pipeline filters

Each filter takes plain data and returns plain data. No filter calls another; the Application Core decides the order. See the [pipeline diagram](../diagrams/README.md#pipeline).

| Filter | Function | Returns | What it does |
| --- | --- | --- | --- |
| 1 | `decode_1(data, limits)` | `DecodedImage1` | Accepts PNG and JPEG only, judged from the content. Raises `DecodeError` with a `DecodeReason` (`UNSUPPORTED_TYPE`, `CORRUPT`, `TOO_LARGE`, `TOO_MANY_PIXELS`). Checks the 10 MB and 12 megapixel limits before decoding pixels, applies EXIF orientation, converts embedded color profiles to sRGB, and places transparency on white. |
| 2 | `extract_palette_2(pixels, color_count)` | `Palette2` | k-means in CIELAB with a fixed seed, on at most 50,000 sampled colors; merges colors closer than CIEDE2000 2.3; assigns every pixel to its nearest color. Ordered by pixel count. |
| 3 | `detect_confusion_3(pixels, palette, profile, threshold)` | `ConfusionResult3` | Flags a pair when it is at least the threshold apart in the original and below it after simulation. Joins linked pairs into groups and masks their pixels. |
| 4 | `enhance_4(pixels, confusion)` | `EnhancedImage4` | Lightness separation: spaces each group 22 CIELAB lightness units apart, between 15 and 90, avoiding the image's other colors. Near-identical colors (closer than the threshold) move together as one tier, so a noisy region is not split into bands. Only masked pixels change. |
| 5 | `check_separation_5(confusion, enhanced, profile, threshold)` | `SeparationReport5` | For each flagged pair, compares the simulated distance before and after. A pair is improved when the distance grew. Also lists pairs that became newly confusable. |

## Color rules

| Module | Functions |
| --- | --- |
| `rules/color_spaces.py` | `srgb_to_linear`, `linear_to_srgb`, `rgb_to_lab`, `lab_to_rgb` |
| `rules/simulation.py` | `simulate(pixels, profile)`: Machado (2009) in linear RGB, interpolated between the 0.1 severity steps in `data/machado_2009.json` |
| `rules/distance.py` | `ciede2000(lab_a, lab_b)` |
| `rules/encode.py` | `encode_png(pixels)` |

Models are in `color_engine/models.py`: `CvdType` (`PROTAN`, `DEUTAN`), `CvdProfile` (type and a severity from 0 to 1), `InputLimits` (10 MB, 12 megapixels), and each filter's output class.

## Defaults

| Setting | Default | Where it is set |
| --- | --- | --- |
| Confusion threshold | CIEDE2000 10 | `CHROMASENSE_CONFUSION_THRESHOLD` |
| Palette colors | 12 | `CHROMASENSE_PALETTE_COLORS` |
| Severity | chosen by the user; the page starts at 1.0 | the page |

## Tests

From the repository root:

```bash
# All engine tests, with coverage (must stay at 70 percent or more)
docker compose run --rm dev pytest src/color_engine/tests --cov=color_engine --cov-fail-under=70

# Engine tests with no web framework installed
docker build --target engine-test .

# The acceptance evaluation; -s prints the report table
docker compose run --rm dev pytest src/color_engine/tests/acceptance -s
```

The simulation is checked against DaltonLens, and CIEDE2000 against the 34 Sharma (2005) test pairs. The decode fixtures in `tests/data/samples/` are regenerated by `make_samples.py` in that folder. The acceptance test needs the held-out images and `labels.json` described in [acceptance-results.md](../acceptance-results.md); until they are added, it is skipped.
