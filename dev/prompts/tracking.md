## Notes

Changes from an increment file that were needed for its verification to pass.

| Increment | Change | Reason |
| --- | --- | --- |
| 02 | The `dev` stage installs `libatomic1` before `playwright install`. | Playwright's bundled Node needs it on arm64 slim images; without it the build exits 127. |
| 03 | `src/color_engine/pyproject.toml` also has the `[tool.ruff]` settings. | Ruff reads only the nearest `pyproject.toml` with `[tool.ruff]`, so engine files would otherwise be linted with defaults. |
| 03 | In `ci.yml`, lint and dependency-rule steps run before the `engine-test` build. | `engine-test` fails with "no tests ran" until increment 04; this order keeps the lint and dependency checks reporting meanwhile. |
| 04 | The interpolation check compares severity 0.45 with the mean of the 0.4 and 0.5 matrices, and 0.5 with its table entry. | The increment's isolation test compared 0.5 with the mean of 0.4 and 0.6, but 0.5 is itself a table step, so linear interpolation does not make those equal. |
| 04 | `encode_png` calls `Image.fromarray(pixels)` without the `"RGB"` mode argument. | Pillow deprecated the mode argument; a uint8 (H, W, 3) array is read as RGB. |
| 04 | Result: mean difference from DaltonLens 0.18 to 0.19 percent, at most 1 unit, for protan and deutan at 0.3, 0.7, and 1.0; 34 Sharma pairs within 0.0001; engine coverage 98.7 percent. | Recorded metric for the CRITICAL checkpoint. |
| 05 | `decode_1` does not change `Image.MAX_IMAGE_PIXELS`. It ignores Pillow's `DecompressionBombWarning` while opening and maps `DecompressionBombError` to `TOO_MANY_PIXELS`. | Setting the module-wide limit would affect every other Pillow caller; the 12-megapixel check runs on the header before `load()` either way. |
| 05 | Fixtures are committed in `tests/data/samples/` with `make_samples.py`, which builds the Display P3 ICC profile byte by byte. | Pillow cannot create a P3 profile; committed files let increment 11 reuse the same fixtures. Display P3 `(180, 120, 60)` decodes to sRGB `(190, 117, 45)`, within 2 units of the expected value. |
| 05 | `lint-imports --config` prints a deprecation warning (import-linter 2.17); the positional form is preferred. | Still works; the commands in `structure.md` and `ci.yml` are unchanged. |
| 06 | Pixels are assigned through their distinct colors: each pixel's RGB is packed into one integer, `np.unique` finds the distinct colors, and only those are matched to the nearest center in chunks. After assignment, each center is recomputed as the mean CIELAB of its pixels. | Meets the chunking note while keeping 12 megapixels fast: a noisy 12 megapixel image (about 207,000 distinct colors) takes 2.4 s on 4 CPUs. |
| 06 | Risk for increment 08: with more clusters than real colors, k-means can split one noisy color into several clusters about 3 CIEDE2000 apart, above the 2.3 merge distance. | If such near-identical clusters land in one confusable group, lightness separation could push them apart and add visible banding. Check this in increment 08's photo-like test. |
