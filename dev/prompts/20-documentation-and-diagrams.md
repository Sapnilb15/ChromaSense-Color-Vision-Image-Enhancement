# Increment 20: Documentation and diagrams

**Status:** Standard
**Depends on:** 19
**SRS IDs:** SRS-NFR-006 (user guide wording); structure (`docs/` tree, `README.md` build and run)

### Main rules

- Write documentation and diagrams only. Change no code.
- Every Mermaid diagram has a matching SVG generated by the `diagrams` service. Do not draw or edit SVGs by hand.
- Describe only behavior that exists. The user guide makes no medical or diagnostic claim.

### Capability

The repository explains how to use, run, and develop ChromaSense, with Mermaid and SVG diagrams of its design.

### What may change

- New files: `docs/code/color-engine.md`, `docs/code/portal.md`, `docs/user-guides/user-guide.md`, `docs/diagrams/README.md`, `docs/diagrams/context.mmd`, `containers.mmd`, `pipeline.mmd`, and their `.svg` renders.
- Remove `docs/user-guides/.gitkeep` and `docs/diagrams/.gitkeep`.
- `README.md`: replace the "Run locally" section with the build and run commands for the new build, and set the status table rows to done.

### What must stay

- `docs/ChromaSense_SRS.docx`, `docs/acceptance-results.md`, `docs/enhancement-evaluation-v0.5.md`, `CHANGELOG.md`, `TEAM_ROLES.md`, and `dev/`.

### Implementation notes

1. Diagrams:
   - `context.mmd` and `containers.mmd`: copy the Mermaid blocks from the Context and Containers sections of `dev/architecture.md`, without the code fences.
   - `pipeline.mmd`: a `flowchart LR` of filters 1 to 5 with each output class on its arrow, and a note that filter 2's palette is reused when only the profile changes.
   - Run `docker compose run --rm diagrams`, which writes `context.svg`, `containers.svg`, and `pipeline.svg`.
   - `docs/diagrams/README.md`: one section for each diagram, with the SVG embedded as `![<text alternative>](<name>.svg)`, a paragraph that describes the same content in words for screen reader users, a link to the `.mmd` source, and the regenerate command.
2. `docs/code/color-engine.md`: the five filters with their contracts, the color rules, the threshold and severity defaults, and how to run the engine tests and the acceptance test.
3. `docs/code/portal.md`: the parts, the use cases, the endpoint table from increment 15, the session lifecycle from Decision 3, and the settings with their environment names.
4. `docs/user-guides/user-guide.md`: the four steps, the input limits, what each status message means, how to compare, how to download, and how to reach the app from another device on the local network. Include the statement from the page footer.
5. `README.md` "Run locally": `docker compose build`, `docker compose up portal`, then open `http://localhost:9090` or `http://<host-ip>:9090`. Keep the Releases section and its link to the `v0.5` tag.

### Verification

- `docker compose run --rm diagrams` succeeds, and `git diff --exit-code docs/diagrams` shows no change afterward.
- Each `.svg` opens in a browser and matches its `.mmd` source.
- A developer who follows only `README.md` and the user guide starts the portal and completes the workflow from a second device.
- Every link in `README.md`, `docs/`, and `docs/diagrams/README.md` resolves.
